The Coco · rungs 2–4

Seal to Settlement

One payload, traced from a node's hands to a settled verdict — every proof-of-authority function it passes through, in the order it passes through them. The chain is a knowledge base, a block is a clause, and every gate below is a Prolog rule a peer can read.

The one rule that shapes all of it: a node is not a process that runs. It is a cocolog invocation that seals or syncs and exits. There is no daemon and no in-memory state anywhere — everything a node knows is rows, so a node that dies has lost nothing and a node that starts has missed nothing.

01

Seal

ledger/node.pl · library(poa)

A payload becomes a block in one goal, and the goal is one transaction. Nothing here is negotiable with a peer: the node is signing its own work.

02

Gossip, and the four gates

ledger_sync/1 · valid_block/6 · extends_known/2

There is no message format. A peer's chain is a knowledge base and a knowledge base is already readable, so gossip is one process running ledger_export/0 against another's kb and offering the result to its own ledger_sync/1. Every offered block is re-verified. A peer's word is a claim.

One attack passes every gate and gains nothing. For any ECDSA signature (r, s) the pair (r, n−s) is equally valid and anyone can compute it without the key — so a malleated signature does verify. It buys nothing, because the block hash covers height, parent, author and payload and not the signature: the malleated block is the same block. Bitcoin's transaction ids covered the signature, and that was transaction malleability.

03

Fork choice

ledger_head/1 · better_head/2 · in_turn/2

A head mark is a candidate, not an answer. Every accepted block gets one, marks are appended and never removed, and the head is whatever the rule says over the whole set — asked afresh on every read. That is why a reorg needs no retraction, and why arrival order, the one thing that differs between nodes, cannot change the answer.

04

What the payload turns out to be

contracts/node.pl · training/worker.pl

Stages 1–3 never looked inside the payload. Now two kinds declare themselves, and both got the chain's guarantees for free — signed by an authority, hash-chained, gossiped, identical on every node — without either needing a deployment protocol of its own.

  1. A1A contract is a list of clauses written into a payload. No bytecode, no ABI, no compiler. contract_deploy_payload/3 → ledger_seal/1
  2. A2Each node walks its agreed chain — not every block it holds, so a contract on a losing fork is never installed. install_from_chain/0 → chain_from/2
  3. A3The fence: every goal in every clause body must be in the vocabulary or defined by the same contract. call/N, =.. and a variable in goal position are refused outright, and meta-predicates are recursed into. contract_admit/3 → admitted | refused
  4. A4Calls enter through one door, and writes are staged — pending until the goal succeeds, dropped on failure or exception, because assertz is not undone by backtracking in any Prolog. contract_call/2 → state_put/2 → flush_pending/1
  1. B1A worker trains in --local with no connection open at all, and prints its weights as facts. Three seconds of gradient descent never sits inside a database turn. train_and_export/1 → param_chunk/3 facts + digest
  2. B2The weights are published as chunked rows — a row must fit in a page and a model does not — and the submission is sealed as an ordinary block. The digest is the join. publish_params/2 · submit_ready/2 → ledger_seal/1

Two layers, two questions. In the choreography alice — a real authority — deploys a contract that reads NODE_KEY out of the environment. The ledger is content: she is entitled to seal, and the block is valid. The fence refuses it. Who may deploy and what may run are different questions with different answers.

05

Settlement

settle_submissions/0 · judge/4 · settle/4

Training is expensive, non-deterministic and unverifiable — two honest workers with the same data land on different weights, and nobody can audit a gradient step after the fact. Evaluation is none of those things. So settlement never asks did you really train this. It asks the only question with a checkable answer: does it work.

And the terminus: where did this model come from

The rung's payload is a query over blocks that are signed, hash-chained and gossiped. A second node that did none of the training settles to the same verdicts, because every step above is deterministic.
